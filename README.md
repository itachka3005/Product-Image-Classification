# Product Image Scraper (Этап "Parsing" из ML Task)

Собирает изображения товаров с asaxiy.uz, texnomart.uz, olcha.uz.

## Главное отличие от первой версии

`output/categories.json` уже заполнен **реальными, проверенными ссылками**
на 5 категорий (смартфоны, ноутбуки, телевизоры, холодильники, наушники) по
всем трём сайтам — это сделано напрямую, без угадывания. Можно сразу
переходить к шагу 2. `discover_categories.py` остаётся в проекте как
дополнительный инструмент, если решишь добавить/поменять категории, но он
не обязателен и не гарантирует результат на texnomart (см. ниже почему).

## Установка (запуск локально в VS Code)

1. Установи Google Chrome, если ещё нет — драйвер подтянется автоматически.
2. Создай окружение и поставь зависимости:
   ```bash
   python -m venv .venv
   source .venv/bin/activate        # Windows: .venv\Scripts\activate
   pip install -r requirements.txt
   ```

## Запуск

```bash
python scrape_images.py
```

Складывает картинки в `dataset/<category_name>/<site>_<n>.jpg`, минимум
`config.IMAGES_PER_CATEGORY_TARGET` (по умолчанию 220, с запасом) на
категорию суммарно по трём сайтам. В конце — сводка по каждой категории.

### Как это работает

Все три сайта используют классическую постраничную пагинацию (`?page=N`
или `/page=N`), а не бесконечный скролл — поэтому скрипт просто идёт по
страницам категории (1, 2, 3, ...) через `site_cfg["pagination_pattern"]`
из `config.py`, пока не наберёт нужное количество картинок, не упрётся в
`MAX_PAGES_PER_CATEGORY`, или пока страница не окажется пустой (категория
закончилась).

Картинки на всех трёх сайтах подгружаются лениво через JS — поэтому вместо
голого `src=` скрипт перебирает список атрибутов `image_attrs` из конфига
(`data-src`, `data-original`, ...).

## Если для какой-то категории/сайта картинок собралось 0 или мало

Значит после моей последней проверки сайт поменял вёрстку. Порядок действий:

1. Посмотри лог — там видно, на какой странице что пошло не так.
2. Если 0 картинок уже на первой странице категории — скрипт автоматически
   сохранит `output/debug_<site>_no_images.png` и `.html`. Открой их и
   сравни с тем, что видно в обычном браузере.
3. Поправь `product_card_selectors` и/или `image_attrs` для нужного сайта в
   `config.py` — открой страницу категории в Chrome, ПКМ по картинке
   товара → «Просмотреть код», посмотри класс контейнера карточки и
   реальный атрибут с URL картинки.

Это единственное место в проекте, завязанное на конкретную верстку сайта —
весь остальной код (пагинация, дедуп, скачивание, логи) универсален.

## discover_categories.py (опционально)

Ищет ссылки на категории в статичном HTML главной страницы. Работает для
asaxiy.uz и olcha.uz (у них ссылки есть в обычном HTML). **Не работает для
texnomart.uz** — это Nuxt SPA, и меню каталога там подгружается через
JS/API уже после первой отрисовки страницы, в самом HTML ссылок физически
нет (проверено напрямую, это не баг парсера). Для texnomart категории в
`categories.json` найдены вручную через прямые запросы к страницам.

Если захочешь добавить категорию для asaxiy/olcha через этот инструмент:

```bash
python discover_categories.py
```

Результат — `output/discovered_categories.json`, откуда руками выбираешь
нужный URL и добавляешь в `output/categories.json`.

## Что дальше по ML Task

`dataset/` — это вход для следующего этапа (Data Preparation): удаление
дублей уже частично сделано на лету (md5-хеш по каждой категории), но
разбиение на train/val/test и финальную проверку битых файлов лучше делать
отдельным скриптом уже на всём собранном датасете (могу сделать следующим
шагом, когда дойдёшь).

## Известные ограничения

- Сайты могут поменять вёрстку/добавить антибот-защиту в будущем — тогда
  `product_card_selectors`/`image_attrs` в конфиге придётся обновить (см.
  раздел выше).
- `IMAGES_PER_CATEGORY_TARGET = 220` — с запасом сверх 200, т.к. на этапе
  Data Preparation часть неизбежно уйдёт (дубли между сайтами, брак).
- Если сайт всё же заблокирует headless Chrome (антибот) — в
  `driver_utils.py` уже есть базовая маскировка (`navigator.webdriver`
  override), но для более агрессивной защиты может понадобиться
  `undetected-chromedriver` — скажи, если столкнёшься с этим, добавлю.
